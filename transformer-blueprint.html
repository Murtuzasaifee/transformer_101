The Big Picture

One sentence goes in, one translated sentence comes out. Click any block below to see exactly what data flows through it.

class EncoderDecoder(nn.Module):
    # Base class: just wires 5 pieces together, no computation of its own
    def __init__(self, encoder, decoder, src_embed, tgt_embed, generator):
        self.encoder = encoder        # reads & understands the input
        self.decoder = decoder        # writes the output, one word at a time
        self.src_embed = src_embed    # input words -> numbers
        self.tgt_embed = tgt_embed    # output words -> numbers
        self.generator = generator    # numbers -> word probabilities

    def forward(self, src, tgt, src_mask, tgt_mask):
        return self.decode(self.encode(src, src_mask), src_mask, tgt, tgt_mask)

    def encode(self, src, src_mask):
        return self.encoder(self.src_embed(src), src_mask)

    def decode(self, memory, src_mask, tgt, tgt_mask):
        return self.decoder(self.tgt_embed(tgt), memory, src_mask, tgt_mask)

Think of this class as the project manager. It doesn't do any of the work itself — it just hands the input to the right specialist in the right order: embed → encode → embed target → decode.

Generator — The Output Layer

The very last step of the model: turning numbers into an actual predicted word.

class Generator(nn.Module):
    "Define standard linear + softmax generation step."
    def __init__(self, d_model, vocab):
        self.proj = nn.Linear(d_model, vocab)   # 512 numbers -> one score per vocab word

    def forward(self, x):
        return log_softmax(self.proj(x), dim=-1)  # scores -> probabilities (log form)
inputx — decoder output, shape [1, 512]# one position's "meaning" vector
proj(x)→[1, 10000] — one raw score per vocab word
softmax→"chats"=92%, "chiens"=5%, ... — sums to 100%

Note: EncoderDecoder.forward() does not call the Generator — it's a deliberately separate final step, applied only when you actually need word probabilities.

AnalogyEverything before this point speaks the model's internal "math language." The Generator is the translator's final act: turning that internal thought into an actual, sayable word.

The Decoder Stack

Also six layers — but each does three things instead of two: look at its own earlier words, look back at the encoder, then think it over.

Encoder layer vs. Decoder layer

Encoderself-attention → feed-forward# 2 steps
Decoderself-attention → cross-attention → feed-forward# 3 steps

The extra step, cross-attention (src_attn), is where the decoder literally asks: "given what I've written so far, which part of the input sentence is relevant right now?"

Part 1 · Model Architecture · Step 5 of 8

Masking

A mask is just a rule that says "block attention to this position." Two independent rules exist, and the decoder combines both.

def subsequent_mask(size):
    # builds a triangular grid: position i can only see positions <= i
    attn_shape = (1, size, size)
    mask = torch.triu(torch.ones(attn_shape), diagonal=1).type(torch.uint8)
    return mask == 0   # flip: True = allowed, False = blocked

allowed to attend blocked
AnalogyPadding mask = ignore blank filler pages in a notebook. Subsequent mask = cover the page with a sheet of paper so you can only read what's already written, never what comes next — otherwise the model would be copying the answer key instead of learning to predict.
Part 1 · Model Architecture · Step 6 of 8

The Attention Mechanism

For every word (query), decide how much to listen to every other word (key), then blend their content (value) accordingly.

def attention(query, key, value, mask=None, dropout=None):
    d_k = query.size(-1)
    # how relevant is every word to every other word?
    scores = torch.matmul(query, key.transpose(-2, -1)) / math.sqrt(d_k)
    if mask is not None:
        scores = scores.masked_fill(mask == 0, -1e9)  # blocked -> ~0 after softmax
    p_attn = scores.softmax(dim=-1)   # turn scores into probabilities per row
    return torch.matmul(p_attn, value), p_attn   # weighted blend of values

Multi-Headed Attention h = 8 heads

Instead of running attention once on the full 512-number vector, the model splits each word into 8 smaller "heads" of 64 numbers, runs attention separately on each, then stitches the results back together. Each head can specialize.

inputQ/K/V — [1, 3, 512]
split→[1, 8, 3, 64] — 8 independent heads
attend→each head runs attention() independently
combine→[1, 3, 512] — concatenated + final linear layer
Analogy8 specialists read the same sentence, each focused on a different kind of relationship (grammar, topic, tone...). Their notes get combined into one final report.

Feed-Forward, Embeddings & Position

After words finish talking (attention), each one privately "thinks it over." Before any of this, raw words first had to become numbers with a sense of order.

Position-wise Feed-Forward Network

def forward(self, x):
    return self.w_2(self.dropout(self.w_1(x).relu()))
    # w_1: 512 -> 2048 (expand), relu, w_2: 2048 -> 512 (compress)
inputx — [1, 3, 512]
w_1+relu→[1, 3, 2048]
w_2→[1, 3, 512]
x→w_1→relu→dropout→w_2→output

Forward: input flows left to right through the network.

AnalogyAttention is a group discussion. The feed-forward step is each word going alone into a private room to think over what it just heard.

Embeddings

A lookup table: each word ID maps to a learned 512-number vector, scaled by √512.

"cats"id 17 → [0.02, -0.5, ...]

Positional Encoding

A fixed sine/cosine wave pattern added on top, so the model knows word order — something attention has no built-in sense of.

"I"+ pattern for pos 0
"love"+ pattern for pos 1
Part 1 · Model Architecture · Step 8 of 8

Assembling the Full Model

One function builds every piece above and wires it into a single, trainable EncoderDecoder.

def make_model(src_vocab, tgt_vocab, N=6, d_model=512, d_ff=2048, h=8, dropout=0.1):
    c = copy.deepcopy
    attn = MultiHeadedAttention(h, d_model)
    ff = PositionwiseFeedForward(d_model, d_ff, dropout)
    position = PositionalEncoding(d_model, dropout)
    model = EncoderDecoder(
        Encoder(EncoderLayer(d_model, c(attn), c(ff), dropout), N),
        Decoder(DecoderLayer(d_model, c(attn), c(attn), c(ff), dropout), N),
        nn.Sequential(Embeddings(d_model, src_vocab), c(position)),
        nn.Sequential(Embeddings(d_model, tgt_vocab), c(position)),
        Generator(d_model, tgt_vocab))
    for p in model.parameters():
        if p.dim() > 1:
            nn.init.xavier_uniform_(p)   # Xavier init -> stable starting weights
    return model

Every reused module (attn, ff) is deep-copied before being handed to a new layer, so layers don't accidentally share weights.

Part 2 · Model Training · Step 1 of 5

Batches & Masking

A small helper object that bundles a batch of sentences and automatically builds the masks the model needs.

class Batch:
    def __init__(self, src, tgt=None, pad=2):
        self.src = src
        self.src_mask = (src != pad).unsqueeze(-2)     # padding mask for source
        if tgt is not None:
            self.tgt = tgt[:, :-1]                      # decoder INPUT: drop last token
            self.tgt_y = tgt[:, 1:]                      # decoder LABELS: drop first token
            self.tgt_mask = self.make_std_mask(self.tgt, pad)
            self.ntokens = (self.tgt_y != pad).data.sum()

    @staticmethod
    def make_std_mask(tgt, pad):
        tgt_mask = (tgt != pad).unsqueeze(-2)
        return tgt_mask & subsequent_mask(tgt.size(-1))  # both rules combined

The target is shifted by one position: the decoder is fed words 1..n-1 and must predict words 2..n. This one-token offset is what turns a sentence into a "next word prediction" training signal.

tgt[<s>, "the", "cat", "sat", </s>]# full sentence
tgt (in)[<s>, "the", "cat", "sat"]# fed to decoder
tgt_y["the", "cat", "sat", </s>]# the answer key
AnalogyLike a fill-in-the-blank worksheet: the decoder sees words 1 through n-1 and must guess word 2 through n. tgt_y is the answer key used to grade it.

The Training Loop

One function, run once per epoch, that pushes every batch through the model and nudges the weights toward less error.

def run_epoch(data_iter, model, loss_compute, optimizer, scheduler, mode="train"):
    for i, batch in enumerate(data_iter):
        out = model.forward(batch.src, batch.tgt, batch.src_mask, batch.tgt_mask)
        loss, loss_node = loss_compute(out, batch.tgt_y, batch.ntokens)
        if mode == "train":
            loss_node.backward()          # compute gradients (backprop)
            optimizer.step()              # nudge every weight slightly
            optimizer.zero_grad()         # clear gradients for next batch
            scheduler.step()              # update the learning rate
    return total_loss / total_tokens

Four things happen per batch, in order: (1) forward pass through the whole EncoderDecoder, (2) compare output to tgt_y to get a loss number, (3) backward pass computes how each weight contributed to that error, (4) the optimizer nudges every weight to reduce it next time.

log lineEpoch Step: 40 | Loss: 4.32 | Tokens/Sec: 1204 | LR: 3.1e-4
AnalogyLike a student working through practice problems: attempt one (forward pass), check the answer key (loss), figure out what to study differently (backward pass), adjust technique slightly (optimizer step), repeat thousands of times.

Optimizer & Learning Rate Schedule

Adam optimizer, plus a custom learning rate that ramps up, then decays — instead of staying constant.

def rate(step, model_size, factor, warmup):
    # ramps UP for the first `warmup` steps, then decays as 1/sqrt(step)
    return factor * (model_size ** (-0.5) * min(step ** (-0.5), step * warmup ** (-1.5)))

Adam is used with β₁=0.9, β₂=0.98. The learning rate itself is not constant: it increases linearly for the first warmup_steps (default 4000), then decreases proportionally to 1/√step.

d_model=512, warmup=4000 d_model=512, warmup=8000 d_model=256, warmup=4000
AnalogyLike easing into a run: warm up gradually so you don't shock your legs (weights), hold a controlled pace, then ease off as you approach the finish line — rather than sprinting flat-out from step one.

Regularization: Label Smoothing

Instead of telling the model the correct word is 100% certain, spread a little bit of confidence across every other word.

class LabelSmoothing(nn.Module):
    def __init__(self, size, padding_idx, smoothing=0.0):
        self.criterion = nn.KLDivLoss(reduction="sum")
        self.confidence = 1.0 - smoothing   # e.g. 0.9 for the correct word
        self.smoothing = smoothing          # e.g. 0.1 spread across the rest

    def forward(self, x, target):
        true_dist = x.data.clone()
        true_dist.fill_(self.smoothing / (self.size - 2))
        true_dist.scatter_(1, target.data.unsqueeze(1), self.confidence)
        return self.criterion(x, true_dist)

With smoothing=0.1 on a 5-word vocabulary, the correct word gets ~90% target confidence instead of 100%, and the leftover 10% is spread across the other words. This hurts perplexity slightly but improves real-world accuracy and BLEU score, because the model learns not to be overconfident.

Target word: index 2 (out of 5 example vocab words)

AnalogyLike a teacher who rewards the correct answer strongly but still leaves a sliver of credit spread around — so the student (model) never becomes smugly overconfident.

Batching for Speed

Real sentences have wildly different lengths. Batching them efficiently matters a lot for training speed.

def collate_batch(batch, src_pipeline, tgt_pipeline, src_vocab, tgt_vocab, ...):
    for (_src, _tgt) in batch:
        processed_src = torch.cat([bs_id, src_vocab(src_pipeline(_src)), eos_id])
        src_list.append(pad(processed_src, (0, max_padding - len(processed_src)), value=pad_id))
    return torch.stack(src_list), torch.stack(tgt_list)

Every sentence is wrapped with <s> ... </s> and padded with <blank> up to a fixed length (max_padding=128), so an entire batch can be stacked into one rectangular tensor.

raw"Zwei Frauen ..."
padded[<s>, "Zwei", "Frauen", ..., </s>, <blank>, <blank>, ...]
AnalogyLike packing boxes of different sizes into a truck — every box gets padded up to the same crate size so they stack neatly, even if some crates are mostly empty space.

Training at Scale

Same recipe as the copy task in Part 2 — just with a real vocabulary, real sentences, and (optionally) multiple GPUs.

def train_worker(gpu, ngpus_per_node, vocab_src, vocab_tgt, ..., config):
    model = make_model(len(vocab_src), len(vocab_tgt), N=6)   # real vocab sizes now
    if is_distributed:
        model = DDP(model, device_ids=[gpu])    # split work across GPUs
    criterion = LabelSmoothing(size=len(vocab_tgt), padding_idx=pad_idx, smoothing=0.1)
    optimizer = torch.optim.Adam(model.parameters(), lr=config["base_lr"], betas=(0.9, 0.98))
    lr_scheduler = LambdaLR(optimizer, lr_lambda=lambda step: rate(step, d_model, 1, config["warmup"]))
    for epoch in range(config["num_epochs"]):
        run_epoch(train_dataloader, model, ..., optimizer, lr_scheduler, mode="train")

Nothing conceptually new here — it's the exact same make_model, LabelSmoothing, rate() schedule, and run_epoch from Parts 1 & 2. The only additions are real data and DistributedDataParallel (DDP), which splits each batch across up to 8 GPUs and averages their gradients.

AnalogySame recipe, bigger kitchen. Splitting work across GPUs is like assigning different chapters of a book to different translators working in parallel, then combining what they each learned.
Part 3 · Real World Example · Step 4 of 5

Checking the Output

After training, greedy decoding produces an actual German-to-English translation. Here's a real example from the trained model.

def greedy_decode(model, src, src_mask, max_len, start_symbol):
    memory = model.encode(src, src_mask)
    ys = torch.zeros(1, 1).fill_(start_symbol).type_as(src.data)
    for i in range(max_len - 1):
        out = model.decode(memory, src_mask, ys, subsequent_mask(ys.size(1)))
        prob = model.generator(out[:, -1])
        _, next_word = torch.max(prob, dim=1)     # always pick the single best word
        ys = torch.cat([ys, next_word.reshape(1,1)], dim=1)   # feed it back in
    return ys

"Greedy" means at every step it takes the single highest-probability next word (no backtracking), appends it, and repeats until it produces </s> or hits max_len.

Source (DE)Zwei Frauen in pinkfarbenen T-Shirts und <unk> unterhalten sich vor einem <unk> .
Ground truthTwo women wearing pink T-shirts and blue jeans converse outside clothing store.
Model outputTwo women in pink shirts and face are talking in front of a <unk> .

Notice it's imperfect but clearly in the right neighborhood — on a dataset this small (Multi30k, ~30K sentence pairs), that's expected. Larger datasets and beam search (trying several candidate words instead of just one) close this gap further.
